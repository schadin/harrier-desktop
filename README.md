# Harrier

Harrier — форк десктопного клиента Cinny для протокола Matrix. Приложение построено на фреймворке Tauri.

> Это форк. Проект не претендует на оригинальность идеи: Cinny — лучший клиент для Matrix, и вся заслуга принадлежит авторам оригинального проекта.
>
> - Оригинальный репозиторий: https://github.com/cinnyapp/cinny-desktop
> - Сайт проекта: https://cinny.in

## Функциональность Harrier

Поверх возможностей Cinny в Harrier реализовано:

- **Пользовательские статусы** — кастомный статус (emoji + текст) через presence протокола Matrix: пресеты с быстрой сменой, восстановление после перезапуска, отправка уведомления в выбранную комнату при смене статуса.
- **Статус присутствия** — отображение онлайн-статуса и времени последней активности пользователей.
- **Системный трей** — иконка в трее со сменой статуса и бейджем непрочитанных сообщений.
- **Системные уведомления** — превью текста сообщения и корректная работа в зашифрованных комнатах.
- **Темы оформления** — Dracula (тёмная) и Alucard (светлая).
- **Иконка** — единый стиль брендинга: цветной лунь на белом круге (прозрачный фон вне круга). Один вид иконки для окна, трея, favicon и PWA.
- **Сортировка комнат в пространстве** — персональная сортировка комнат в сайдбаре пространства и лобби (ручная / по алфавиту / по последней активности); задаётся в лобби, сайдбаре или настройках пространства, плюс вариант по умолчанию для всех пространств.
- **Исправления** — вставка изображений из буфера обмена и надёжное прикрепление файлов.
- **Статус отправки сообщений** — индикатор в ленте собственных сообщений: `Clock` при отправке/шифровании и `Cross` при ошибке (работает во всех комнатах), повторная отправка и локальное удаление неудачных сообщений через меню сообщения, уведомление о причине ошибки отправки.
- **Миграция настроек** — перенос конфигурации и данных из Cinny при первом запуске без удаления исходных данных.
- **Интеграция с окружением** — скрытие заголовка окна под Niri.
- **Интеграция DsTaskBot** — команды бота задач (`!list`, `!close N`, `!file N`, `!help` и др.) с автодополнением и slash-шорткатами `/dstask`, карточки задач, отчётов и справки со списком команд в таймлайне, сворачивание служебных сообщений (в личке — только в переписке с ботом).
- **Веб-legacy** — автономная веб-версия на GitHub Pages в репозитории [schadin/harrier](https://github.com/schadin/harrier).

## Структура монорепозитория

```text
harrier-desktop/
├── client/       # React/TypeScript-клиент и его история
├── src-tauri/    # Десктоп-обёртка на Tauri/Rust
└── scripts/      # Сборочные и релизные скрипты
```

## Локальная разработка

Потребуются Rust, Node.js и системные зависимости Tauri.

```sh
git clone https://github.com/schadin/harrier-desktop.git
cd harrier-desktop/client
npm ci
cd ..
npm ci
npm run tauri dev      # запуск в режиме разработки
npm run tauri build    # продакшен-сборка
```

В существующих клонах с подмодулем перед переходом на новую ревизию выполните:

```sh
git submodule deinit -f cinny
git pull
rm -rf .git/modules/cinny
```

## Версионирование и релизы

Версия синхронизируется командой `npm run bump <version>`: обновляются
`package.json`, `src-tauri/Cargo.toml`/`Cargo.lock` и `src-tauri/tauri.conf.json`.
Версия меняется только по явной команде.

Скрипт `scripts/update-version.mjs` дополнительно выводит числовую версию
`bundle.windows.wix.version` для MSI-инсталлятора: WiX не принимает
человекочитаемый pre-release, поэтому номер сборки переносится в четвёртое поле
(`4.12.6-harrier.6-beta` → `4.12.6.6`). macOS и Linux собираются из полной
semver-версии.

Релизы публикуются как GitHub Release только в этом репозитории (workflow
`tauri.yml`): Windows (MSI), Linux (deb/AppImage), macOS (DMG). Веб-legacy
выпускает собственные независимые релизы только при необходимости.

Полный процесс выпуска предрелизов и релизов — чек-листы, оформление release
notes, создание релиза и откат при сбое — описан в
[docs/RELEASING.md](https://github.com/schadin/harrier-project/blob/main/docs/RELEASING.md)
зонтичного репозитория.
